ARCHITECTURAL PATTERNS TO APPLY
================================================================================

1. CALLBACK PATTERN (UI Updates)
   - Managers pass callbacks in constructor
   - Execute callbacks after operations complete
   - Decouples managers from UI

2. OBSERVER PATTERN (Theme Changes)
   - Components implement ThemeObserver
   - Register with ThemeManager
   - ThemeManager notifies all on change

3. BUILDER PATTERN (Complex Dialogs)
   - Replace 200+ line dialog setup
   - Use fluent API for field configuration
   - Reduces constructor clutter

4. FACADE PATTERN (Component Access)
   - Create EditorFacade for codeEditor
   - Facade handles state synchronization
   - Reduces direct component coupling

5. MANAGER COMPOSITION (Central Orchestration)
   - Create IDEManager that composes all sub-managers
   - Python3IDE delegates to IDEManager
   - Single entry point for manager initialization

================================================================================
KEY REFACTORING BARRIERS
================================================================================

1. Script Management <-> Theme Integration
   - Script operations need to trigger tree rebuild
   - Tree rebuild needs theme colors
   - Solution: Observer pattern for tree updates

2. Code Editor State Management
   - Changes tracked by UnsavedChangesTracker
   - Content loaded by loadScript()
   - Saved by saveScript()
   - Solution: Create EditorStateManager

3. Terminal Session Lifecycle
   - Created when switching to Terminal mode
   - Destroyed when switching to Python mode
   - Needs status updates during operation
   - Solution: TerminalSessionManager with lifecycle callbacks

4. Component Initialization Order
   - Some components depend on theme state
   - Theme applied after initialization
   - Solution: Two-phase initialization or post-theme setup

5. Dialog Theme Integration
   - DarkDialog uses global theme state
   - Each dialog must apply current theme
   - Solution: Central DialogThemeManager
